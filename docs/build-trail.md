# Versioned PRDs — build trail

Historical reference for how the codebase got here. Most of the load-bearing rationale also lives in `decisions/` as ADRs. Load this file when you need long-form context for a specific version; otherwise CLAUDE.md's decision-log section and the ADR index are usually enough.

- **v1.2** — baseline: auth, onboarding, subscription, i18n
- **v1.3** — WAC, sales module, khata view enhancements
- **v1.4** — partial payments, customer expansion, walk-ins
- **v1.5** — product type uniqueness, opening stock, fuzzy search, POS redesign
- **v1.6** — ledger hardening: stored balance, reversals, occurred_at, append-only
- **v1.7** — design system revamp (mint→navy palette, Urdu font fix, DataTable primitive)
- **v1.8** — db hardening: RLS audit, search_path, FK indexes, locks, money precision, view security_invoker, append-only across financial tables
- **v1.9** — stock-in hardening: suppliers, landed-cost pro-rata allocation, bidirectional cost calc, searchable product/supplier comboboxes, MTD-default list with pagination, Effect-on-Inventory snapshot fix
- **v2.0** — *superseded by v2.1*. UoM + first-class pack pricing was spec'd and partially built (migrations 0026/0027), then walked back. `MVP_v2.0_UNITS_OF_MEASURE.md` is historical reference only; do not implement against it.
- **v2.1** — stock-in unit handling: `units_of_measure`, `product_packs` (no price column — packs are stock-in shortcuts only), `products.is_scan_only`, `purchase_items.{pack_id, pack_qty, pack_base_qty_snapshot, qty_in_base}`. Sales stay in base units; `record_sale` byte-equivalent to v1.6. Stock display view exposes `whole_packs` + `remainder_base` directly so the frontend never recomputes breakdowns. `record_purchase` accepts pack-shaped lines; `define_pack_inline` auto-creates UoMs at stock-in time. POS quick-add buttons; scan-only enforcement.
- **v2.2** — customer tiers + per-line discounts + manual override. `customer_tiers` (named %-only groups, default per shop), `customers.tier_id`, invoice snapshot of tier id/percent/amount/override-type/override-value, `sale_items.line_discount_*`. `record_sale` rewrites: stacking order is **negotiated price → per-line discount → tier (or override) → service charge added last**. Discounts apply to items only, never service. *Partially reverted in v2.3 — see below.*
- **v2.3** — fixes from v2.1/v2.2 testing. (a) Tiers reduced to pure customer categories: `customer_tiers.discount_percent` dropped; tiers no longer auto-discount sales. The popup is now the only source of an invoice-level discount. (b) Invoice columns renamed `tier_*` → `sale_discount_*` (4 columns + recreated `invoices_sale_discount_consistent` constraint). (c) Overhead allocation rewritten: stored as new `purchase_items.line_overhead_amount` via **largest-remainder** method in `record_purchase` (overhead distributed pro-rata by line value, leftover penny goes to the highest-value line). The legacy `overhead_per_unit` column is kept for back-compat — drop in a future cleanup. (d) `search_products` is name-only (combined name+type GIN index dropped; relevance preserved + `p_only_in_stock` filter). (e) Frontend: PurchaseDetail row indices precomputed (DataTable's `cell` doesn't pass index — was rendering NaN); columns restructured to # / Product / Qty / Unit cost / Subtotal / Overhead / Total with explanatory note; "Cost change" replaces "Δ"; per-piece cost shown under unit cost when pack base_qty > 1; supplier dropdown widened. (f) POS: tier auto-discount logic removed; customer card with tier chip pinned at the top of the cart; cart column headers added; "Override" → "Apply discount"; submit payload `tier_override_*` → `sale_discount_*`; sale discount cleared on customer change and on submit success.
- **v2.4** — UI revamp + dark mode (no business-logic changes). See the dedicated **Design system (v2.4)** section in CLAUDE.md for the canonical rules; summary here for the build trail. Brand scale flips teal/navy → amber. Dark mode via a `[data-theme="dark"]` block in `tokens.css` — only semantic tokens flip, raw scales stay constant. `ThemeModeProvider` (`src/lib/themeMode.tsx`) handles `system | light | dark` and writes `data-theme` on `<html>`+`<body>`; `getTheme(direction, mode)` flows the resolved mode into MUI's `palette.mode`. Sun/moon toggle in TopBar. New token family for ambient warmth: `--surface-card` (warm undertone for cards), `--shadow-card` / `--shadow-card-hover` (amber-bloom), `--body-glow` (radial gradient painted via `body::before`). Light-mode primary shifted from brand-700 brown to brand-500 bright amber with dark contrast text. `<Card>` default = no shadow (elevated keeps the bloom). Dropdown overrides centralised in `MuiMenu` / `MuiAutocomplete` / `MuiPopover` so every popup shares one container language. Sidebar active state simplified to an amber pill. Typography unchanged.
- **v2.5** — product detail page + `product_categories` entity. (a) `/products/:id` now renders a `ProductDetailPage` (header, fields, packs, last-10 activity feed); editing happens in a `ProductEditDialog` modal. (b) POS gets a right-side drawer (bottom sheet on mobile) showing the same `ProductDetailBody` plus a sticky "+ Add to cart" footer button — cart state is preserved across drawer open/edit/close. (c) `products.type` (free text) is promoted to a `product_categories` table per shop; `products.category_id` is a NOT NULL FK; unique index swapped from `(shop_id, name, type)` to `(shop_id, name, category_id)`. (d) Product form's Type input is replaced by a `CategoryCombobox` with inline "+ Create new category" dialog. (e) `/products` list gains a URL-synced single-select `?category_id=` filter; the trailing edit/archive icons column is dropped (archive moved into the edit modal's Active toggle); a leading eye-icon column is the explicit "View details" affordance. (f) POS picker gains the same eye icon + "Add to cart" column header + center-aligned [+] button. (g) Three new SECURITY DEFINER RPCs (`search_categories`, `create_category_inline`, `update_category`); `search_products` / `_count` gain `p_category_id`; `create_product_with_opening_stock` prefers `p_category_id` but falls back to `p_type` so stale clients don't break. (h) `products.type` is kept and snapshotted from the category name — drop in a future cleanup migration.
- **v2.6** — foundational variant refactor (SILENT — zero user-visible changes). `products` becomes a template; stock/price/cost moved to a new `product_variants` table; every existing product gets a synthetic default variant carrying the old values. `sale_items` / `purchase_items` / `product_packs` repointed to `variant_id` (with the legacy `product_id` kept in sync via the `sync_product_id_from_variant` trigger). All stock-touching RPCs (`record_sale`, `record_purchase`, `create_product_with_opening_stock`, `search_products`, `define_pack_inline`, `update_pack`, `deactivate_pack`) rewritten to operate on `product_variants`. `search_products` reads through the `product_with_default_variant` compat view so v2.5-era hooks see the same row shape. Six audit queries (§6 of the spec) return zero rows post-migration. Sets up the v2.7 variant-management UI without leaving any "is this a variant product?" branches in legacy code. Migrations 0037–0044.
- **v2.6c** — Stage 2 profit-bug hardening + no-JS-Number-on-money discipline (no user-visible business change). (a) `sale_item_financials` view performs largest-remainder allocation of `invoices.sale_discount_amount` across lines and exposes `line_value` / `line_revenue` / `line_cost` / `line_profit`; `invoice_financials` aggregates per-invoice (`items_subtotal`, `revenue`, `gross_profit`, `gross_margin_percent`, `outstanding`). Both views are `security_invoker = true`. SaleDetail and Dashboard now read the same canonical numbers. (b) `monthly_summary` view rewritten to aggregate from `invoice_financials` rather than recompute. (c) `invoices.outstanding` becomes a generated `numeric(12,2)` column (`greatest(0, total − amount_paid)`) so the sales list reads outstanding credit without JS subtraction. (d) `purchase_item_financials` view exposes per-line `line_subtotal`, `line_overhead` (effective: largest-remainder result or legacy fallback), `line_total`, and `cost_delta`. (e) `daily_sales_7`, `expenses_by_category_mtd`, `total_outstanding` views replace JS reduce calls in reports + dashboard hooks. (f) Three new audit queries (7/8/9 in the suite) — stored-total consistency, financials math sanity, ledger debit ≡ outstanding — return 0 rows. (g) ADRs: profit-bug root cause, single-source-of-truth, audit-suite extension, record_sale transaction integrity (deliberate-failure-verified), cost_at_sale snapshot timing, decimal precision audit, no-JS-Number-on-money discipline. Migrations 0051–0056.
- **v2.7** — variant management UI on top of v2.6. (a) Shop-wide `variant_attributes` + `variant_attribute_values` + `product_variant_attribute_values` tables; new Settings → Variant Attributes page manages them. (b) Product create form gets a "Has variants?" toggle; on, replaces the single price + opening stock fields with a matrix builder. Up to 3 attributes per product (enforced at RPC + UI), cross-product generates combinations as a flat review table with auto-suggested editable SKUs and per-row price overrides. (c) Multi-variant product detail page renders a variants table with per-row inline edit and "+ Add variant" that calls `add_variant_to_product`. (d) Stock-in implements the spec's expanding-line fallback (§7.6) — one variant per stock-in line, not a 2D matrix grid; v2.3 largest-remainder overhead allocation works unchanged. (e) POS multi-variant rows show "X variants" + price range instead of stock/price; "Pick variant" button opens a dialog with click-to-add; cart line + receipt render `"Tracksuit AAA — Red / M"` labels via `product_variant_full.variant_label`. (f) Three new RPCs (`create_product_with_variants`, `add_variant_to_product`, 8 attribute/value CRUD), one new view (`product_variant_full`), `product_with_default_variant` widened with multi-variant aggregates (variant_count, min_price, max_price). Migrations 0045–0048.
- **v2.8** — batch tracking (per-product opt-in via `products.has_batches`). Stock-in captures `batch_no` + manufactured / expiry / `supplier_warranty_days` per stock-in line. Sales use FEFO (First Expire First Out) via `record_sale` — `cost_at_sale` on batched-product rows is the BATCH's `cost_per_unit` (not `variant.avg_cost`) so `invoice_financials.gross_profit` is accurate per batch. A single cart line can produce multiple `sale_items` rows when it spans multiple batches (line_discount_amount split via largest-remainder by qty). Dashboard surfaces `batches_expiring_soon` and `batches_warranty_expiring_soon` views; the widget auto-hides for shops without any batched product. Shop-level alert defaults in Settings (`shops.default_expiry_alert_days` / `default_warranty_alert_days`) with per-product overrides on `products.{expiry_alert_days, warranty_alert_days}`. `deactivate_batch` write-off decrements `variant.stock` directly (temporary — v2.10 inventory_adjustments ledger will replace). `inventory_batches` row is mostly append-only: only `qty_remaining`, `is_active`, `notes` are mutable post-insert (enforced by `batch_immutable_fields` trigger). Migrations 0057–0058. ADRs 2026-05-12-batches-vs-serials-mutually-exclusive, -fefo-override-ux-pick-batch-link, -batch-cost-vs-avg-cost-on-sales, -multi-batch-line-split-data-model, -batch-deactivation-temporary-pattern, -shop-level-alert-defaults-with-product-overrides, -batch-immutability-rules.
- **v2.8.1** — pricing/stock decoupled from product creation. `create_product_with_opening_stock` and `create_product_with_variants` make `p_price`/`p_default_price` nullable, gain `p_has_batches`/`p_expiry_alert_days`/`p_warranty_alert_days`, and raise `cannot_seed_opening_stock_for_batched_product` if has_batches=true AND opening_stock>0. Product create form drops opening-stock + opening-cost inputs; selling price is optional; "Inventory behavior" section (has_batches toggle + per-product alert window overrides) lives on the create form alongside the edit dialog. Variant matrix builder drops the per-row opening-qty column. NewPurchasePage gains a "This is opening stock" checkbox that flips `purchases.is_opening`. ProductDetailBody surfaces a "Selling price not set" banner with a "Set selling price" CTA when `price IS NULL`. POS naturally hides null-price products via the existing 0-stock filter + record_sale's `variant_not_sellable` guard. Migration 0060; ADR `2026-05-12-pricing-decoupled-from-product-creation`.
- **v2.8.2** — partial write-off + auto-deactivate when empty. New RPC `record_partial_writeoff(batch_id, qty, reason)` decrements `variant.stock` and `batch.qty_remaining` by exactly `qty` and appends a dated note; supports RTV / damage / partial-loss workflows without recreating the batch. New BEFORE UPDATE trigger `batch_auto_deactivate_when_empty` fires on the `qty_remaining > 0 → 0` transition and flips `is_active = false` automatically — empty batches stop cluttering the active list. WriteOffBatchDialog gains a "Qty to write off" input that defaults to `qty_remaining`; always routes through `record_partial_writeoff` (the trigger handles the full-batch case). `deactivate_batch` kept for back-compat. New invariant: no batch can have `qty_remaining = 0 AND is_active = true`. Migration 0061; ADR `2026-05-12-partial-writeoff-and-auto-deactivate`.
- **v2.8.3** — visibility fixes for two silent failure modes. (a) `batches_already_expired` view surfaces batches past `expiry_date` with `qty_remaining > 0` — the v2.8 alert widget dropped them the day they expired, allowing silent accumulation. New `ExpiredStockWidget` on the dashboard with danger-tone styling, per-row click navigates to the product detail, "Write off all..." bulk dialog loops `record_partial_writeoff` over each. New route `/inventory/expired` for the full list. (b) `product_with_default_variant` gains `has_null_price_variant`; `search_products` + `_count` gain `p_needs_pricing`. Catalog list renders "Set price ⚠" warnings for null-priced products (single-variant) or "Rs X – set price" for partial multi-variant pricing. URL-synced "Needs pricing" filter chip in the catalog filter bar. Migration 0063; ADRs `2026-05-13-expired-stock-as-separate-dashboard-section`, `2026-05-13-bulk-write-off-loops-existing-rpc`, `2026-05-13-has-null-price-variant-aggregate-on-view`.
