# 0027 — At most 3 variant attributes per product

**Date:** 2026-05-12
**Ticket:** v2.7
**Status:** Accepted

## Context

A 1-attribute product (Yoga Mat with Size) lays out as one row of cells.
2 attributes (Tracksuit with Color × Size) lay out as a 2D grid. 3 attributes
(iPhone with Storage × Color × something else) start to need either tabs
or a 3D flattening. 4+ attributes have no clean UI representation in 2D
print or screen real estate.

The spec asks for a hard limit so the matrix UI can be designed against a
known shape.

## Decision

A product can have at most 3 variant attributes. Enforced in
`create_product_with_variants` with `raise exception 'too_many_attributes'`
when `array_length(p_attribute_ids, 1) > 3`. Frontend matrix builder's
"+ Add another attribute" hides at 3.

## Alternatives considered

1. **Unlimited.** Rejected — no UI representation; performance edge cases
   (a 4-attribute product with 5 values per attribute = 625 variants
   generated by default).
2. **2 maximum.** Rejected — iPhones (Storage × Color) are 2D, but a real
   case like "Phone Case (Phone Model × Color × Finish)" wants 3. The
   spec's user cases include 3-attribute products.
3. **Configurable per shop.** Rejected — premature flexibility.
   Universal-product-catalog systems may need this in v3; SME tier
   doesn't.

## Consequences

- A new product with 4 attributes is impossible. If a real customer
  requests this in the future, revisit the limit and the UI.
- `add_variant_to_product` enforces attribute composition match against
  the product's existing variants, so once a product is created at 2
  attributes it stays at 2.
- Documented in CLAUDE.md gotchas.
